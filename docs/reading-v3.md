# 据课推演 V3

V3 把原始课盘、原典条句、白话释义和本次问题推断分开。用户输入任意具体事项，模型先整理语义，再选择程序提供的已核原则与盘面条件解释；类别是检索辅助，不是整篇答案模板。

## 问题理解

旧 subject/object/goal/timeframe/background 仍要求是用户原话中的片段。新增 meaning-v1 保存开放主题、问题类型、主体角色、动作、多个对象、目标、时间和原文引用。explicit、paraphrase、default_self、unknown 分开保存；默认本人可以通过补充更正。时间保留“晚上”“下周”等文字，不由识别器伪造日历日期。

模型不能因为缺少预算、准备程度等现实背景就把明确事件退回“事项不明”。只有真正的多问、指代不明或类别冲突才澄清，一轮最多两个问题。三种答案键 scope/category/object 可共存，以容纳先前补充加本轮澄清。未知品牌不设白名单，类别由实际动作决定。

## 解释与原句

readingContext 包含原课全部事实、不写回原盘的派生事实、经核字的来源快照、稳定 clauseId 与条件评估。procedure 只说明计算；principle 说明一般传统关系；judgement 说明满足的局部条件。unknown 不能作为成立依据。

模型返回 summary/tendency、focus、reasoning、synthesis、advice 和 limitations。每项取用与推演引用同一评估内的事实及原句。所有已命中的 judgement 必须出现在推演中，支持、阻碍及限制论点必须进入综合判断。页面从快照显示原句和影印原页；模型只写释义和当前应用，不能自造古文。建议允许为空，最多三项，每项承接某条推演。

程序校验引用闭环、盘值一致性及已编码限制，不宣称自动证明所有自然语言推论正确。传统定性倾向不等于统计概率，不输出保证、伪造概率、精确应验日期、未核年命填实或人物指控。未核复杂旺衰、神煞和精确应期不参与肯定判断。

## 报告与更新

新报告 schemaVersion=3，使用 guanxiang.reports.v3；有效 v1/v2 继续读取，不改旧存储。按报告 ID 合并，v3 优先；不同报告即使创建时间相同也保留。最近列表最多30份。

readingRevisions 保存完整的新解读版本，activeReadingId 决定页面、打印和导出的当前版本。旧 interpretation/legacyInterpretation 及其上下文保留为历史版。每版保存 intent、answers、context、interpretation、meta、原问 questionAskedAt 与生成 createdAt。原问题、课号、起课时间、四课三传和咨询关系不改变。

支持 engine 0.2.0 / daquan-v1.0.0 的原课可独立升级文献和解释；未知引擎只读，不悄悄改标为现版。新请求阶段仅修改组件私有草稿，成功校验后才追加完整版本，取消、错误及迟到响应不替换原版。损坏的单版记录隔离，不让整个课盘消失。所有字符串在归档校验前统一移除密钥形态内容，保持原文引用与脱敏后的正文一致。

## 调用与展示

V3 理解请求25秒、3500输出token；解读请求120秒、24000输出token（含模型内部推演），使用 DeepSeek Flash 的低强度思考，只读取最终 content，不展示或保存其 reasoning_content。参数按[官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)配置。一次流程最多两次请求，无自动重试。用户自行填写密钥并勾选发送同意，GitHub Pages 和仓库不保存密钥；不新增服务端或付费域名。

若模型把 synthesis 对象展平成同名字符串与根 reasoningIds，且其余字段完全吻合，客户端只将这两个已有值无损装回对象；advice 仅多出合法、唯一、没有被引用的展示 id 时移除该编号，再经过同一严格校验。不补引文、改结论或发起修复请求。历史存档仍只接受正式结构。

展示顺序为顶部简断、原始课盘、问题理解、取用、逐项推演、综合、具体建议。引文与本问应用就近对应，程序边界及历史原文折叠备查，删除原先通用现实核查清单。保持深墨与哑金界面，并按811像素和390像素检查阅读与引用布局。

测试须分别记录纯模拟、真实模型与生产验证，不能互相替代。最新实际结果见 validation.md。
