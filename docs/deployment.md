# GitHub Pages 发布与浏览器直连解读

目标网址：`https://999888666jiang-dev.github.io/daliuren/`。当前架构将静态页面发布到 GitHub Pages，由使用者的浏览器直接请求 DeepSeek 官方接口。排盘、规则条件检查、引文选择和报告处理都在本机浏览器完成。

不需要 Cloudflare 账户、Worker、D1、邀请码或自建服务端；不存在应用层的全站每日配额。模拟测试、真实模型评估和生产浏览器检查分别记录，互不替代。实际验收结果统一记录在 [validation.md](validation.md)。

## 本地开发

推荐 Node.js 24，与 `.github/workflows/pages.yml` 一致。

```sh
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173/daliuren/`。模型密钥只在网页输入，开发与构建都不需要配置密钥环境变量。

```sh
npm test
npm run build
npx playwright install chromium firefox webkit
npm run test:e2e
```

`npm test` 运行排盘、历法、引文、意图、条件判断、客户端响应校验、密钥状态和报告兼容测试。`npm run test:e2e` 在 Chromium、Firefox、WebKit 中使用隔离的模拟上游；Playwright 会按配置启动开发服务器。测试不调用付费模型，测试凭据不是真实密钥。静态生产包可用 `npm run preview` 本地预览。

## GitHub Pages 发布

1. 将代码保存在自己的公开 `daliuren` 仓库，在仓库 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**。
2. 当前 Vite `base` 为 `/daliuren/`；仓库名改变时需同步修改站点子路径及相关测试地址。
3. 推送到 `main` 或手动运行 **Verify and publish** 工作流。拉取请求只执行验证，不发布。
4. 工作流执行 `npm ci`、`npm test`、`npm run build`，安装浏览器并运行模拟上游的 `npm run test:e2e`；通过后上传 `dist/`，由 Pages 部署任务发布。
5. 打开工作流返回的网址检查页面和手机深链接。真实模型验收需由使用者在网页填写自己的密钥并明确发起，不能由 CI 自动代做。

工作流不读取或传入 DeepSeek 密钥，不需要模型相关的 GitHub Actions Secret，也不需要 `VITE_API_BASE_URL`。不要把密钥放入源码、`VITE_*` 变量、构建产物或仓库文件。构建时注入的值会进入公开 JavaScript，GitHub Secret 无法将浏览器端运行所需的值变成服务器秘密。

公开仓库的 GitHub Pages 可随 GitHub Free 使用，提供的是静态托管。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。DeepSeek 调用按模型账户的余额、额度和计费规则处理，网站免费托管不抵扣这部分费用；不要把 API 账户额度与聊天产品使用额度混为一谈。[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)。

## 密钥的本机使用

网页默认以密码输入框显示密钥，可切换显示/隐藏。填写后的未保存值只供当前页面会话使用；点击“保存到此设备”才写入本机 `localStorage`，下次在同一浏览器来源打开时自动读取。保存动作不调用模型；更改已保存值后需明确更新。

本机保存不是加密保险库。同一浏览器、同源页面脚本能读取该存储；GitHub Pages 同一 `github.io` 域名下的其他项目路径也属于同源。只在自己信任的设备与浏览器保存。清除按钮会清空页面值并尝试删除本机记录；浏览器拒绝删除时会提示手动清除此网站数据。清除本地值不等于撤销 DeepSeek 账户里的密钥，需要撤销时到官方账户管理。

密钥只作为发往固定官方接口的 `Authorization` 头，不放入模型消息、问题网址、报告保存、JSON 导出或打印内容。本机存储被浏览器禁用时，页面允许临时填写并明确报告保存失败，不假装已经持久保存。

## 一次解读流程

1. 起课时默认自动识别事项，也可手动选类。本地初步识别与后续模型理解在界面中分别标示；问题文字不参与排盘。
2. 使用者填写密钥并勾选发送说明后，主动点击生成。第一轮模型请求只整理问题、主体、对象、目标和缺失信息，不重排课盘。
3. 必要时只澄清一轮，最多两个问题。补充答案沿用原起课时间；留空的内容保持未明确，不自动补造事实。
4. 第二轮请求发送问题、意图与补充答案、必要课盘事实、已核摘句和规则条件评估。返回内容经本地结构、事实 ID、引文 ID 与适用条件校验后才展示。

一次启动的流程最多两次模型调用。当前模型固定为 `deepseek-flash`，接口为 `https://api.deepseek.com/chat/completions`，使用 JSON 输出、非流式响应，关闭思考模式。问题理解限 15 秒、1200 输出 token；解释限 35 秒、4096 输出 token。这些是客户端请求限制，不是保证金额或服务时延。[DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

没有自动重试或失败后自动修补答案的额外请求。密钥无效、余额不足、限流、超时、网络/跨域失败、内容截断或返回校验失败时显示对应状态，课盘与原文仍可查看。主动重试会开始新的流程，也可能再次计费。取消、切换页面或关闭标签页会停止客户端等待，但已经发出的请求可能仍产生费用；断网后未收到的答案无法从本项目服务器取回。

此方案依赖使用者浏览器可访问官方接口及官方跨域策略；源码与模拟测试不能替代实际浏览器联调。遇到跨域错误应如实记录，不能将模拟响应替换成真实成功状态。

## 古籍证据与解释的界限

17 条正式已核摘句由本地资料库直接显示，模型不得创作古文、补造书名或引文网址。传统解释必须关联本课条件满足的规则与对应证据；条件不满足、未判定和不适用的记录不能被包装成肯定判断。针对问题的现代推测与行动建议单独标示，结构校验不能保证语义判断永远正确。

当前公开 42 张必要扫描页；26 个固定古课中 23 个已逐页核验、2 个转录待核、1 个独立手算。七个完整扫描原件只在本地归档，不上传 Pages。详见 [sources.md](sources.md) 与 [algorithm.md](algorithm.md)。

## 报告 v2 与隐私

新报告使用 `schemaVersion: 2`，保存课盘、原文快照、意图、澄清答案、规则评估及可选模型解读/版本信息；新课及通过校验的解读自动写入本机最近 30 份记录，用于恢复和重复问题检查。JSON 导出同样先执行格式校验；页面合并读取有效 v1/v2 记录，并最多显示最近 30 条。存储失败明确提示，当前页仍可导出。

新报告额外保存原起法、真实/虚拟时支、报数、事项编号、现实变化与来源关联。原事项报告与原盘报告分别记录；续问保留原课号但使用新的报告编号。`#/result/<报告ID>` 只引用本设备已有记录，不包含问题正文；手机与电脑可以打开同一网站，但不能用该路径跨设备读取本机报告。来源不匹配的模式元数据会被拒绝；旧版报告不按新版引擎重新计算。

GitHub Pages 无应用服务端，无法安全向所有访客自动派发一把共用模型密钥。因此每台设备须在网页临时填写或主动保存密钥；只发给朋友网站地址不会暴露密钥。免费排盘、原典与本地事项分析无需密钥，AI 服务仍使用密钥所属账户额度。

有效 v1 报告兼容读取，旧 AI 内容标为“旧版解读”，不冒称通过新版条件校验。损坏的可选解读或引文字段会提示并保留可用课盘；缺少原文快照时，不用当前资料补装成当时的引用。规则或文献版本不同的历史报告保留原有内容，暂不追加新版 AI；不应仅为版本更新重复占问同一件事。密钥不属于报告格式，清除报告与清除密钥是各自独立的操作。

本项目没有应用服务端保存问题、课盘、密钥或答案，报告不自动同步到其他设备。调用前明确告知将问题、补充信息及必要课盘资料发送给 DeepSeek；本机记录也可能包含用户写入的问题隐私。“无项目服务端保存”不等于第三方零留存：DeepSeek 按自身政策处理请求，GitHub Pages 也会有平台访问记录。[GitHub Pages 数据收集说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection)。
